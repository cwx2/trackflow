## 操作流程

**第一步：打开系统，看一眼总体情况**

1. 访问 http://localhost:3000，登录
2. 看工单列表或仪表盘，了解当前项目状态
   - 有多少工单在进行中？有多少还没开始？
   - 最近有没有新增的 Bug？优先级高吗？
   - 本周有什么工单要交付？

**第二步：提一个新工单（情况 A）**

模拟一个真实场景，认真填写：
- **类型**：根据情境选 Bug / Feature / Task
- **标题**：写一个具体的、有意义的标题（不要写"测试工单"）
- **描述**：认真写3-5行，包括背景、期望效果、验收标准。可以用格式（列表、加粗）让描述更清晰
- **优先级**：根据重要程度选
- **Sprint**：Critical 的放当前 Sprint，其他的放 Backlog
- **标签**：如果有相关标签，加上

提交后打开刚创建的工单，确认内容都保存正确了。再看看有没有要加关联的工单（比如这个 Bug 关联了哪个 Feature）。

**第三步：补充已有工单的说明（情况 D）**

找一个描述比较简单的旧工单，用评论补充一些说明：
- 写一条评论，说明背景信息或补充验收标准
- 如果有截图或文档，上传为附件
- 看看评论发出去之后格式对不对，有没有显示乱

**第四步：做 Sprint 规划（情况 B）**

进 Sprint 管理或 Backlog 视图：
- 看 Backlog 里有哪些工单，按优先级浏览
- 把高优先级的工单加入下一个 Sprint
- 给 Sprint 加一个目标说明
- 如果 Sprint 还没建，新建一个并填好日期

**第五步：查看进度报表（情况 C / E）**

进报表页面：
- 看各状态工单数量分布，感觉数据准不准
- 看有没有燃尽图或趋势图，数据有没有意义
- 看一下按人分组的工单数，有没有谁工作量明显不均衡
- 如果需要，试着创建一个自定义报表

**第六步：随手记录遇到的问题**

操作过程中遇到任何不对劲都记下来，比如：
- 工单创建弹窗某些字段找不到或者用起来很别扭
- 描述编辑器格式不对，粘贴进来乱掉
- 报表页面数字是 0 或者明显跟实际不符
- Backlog 视图找不到或者用起来不顺
- Sprint 规划操作步骤太复杂
- 某个字段保存后刷新又没了
- 工单列表排序或筛选结果感觉不对
- 界面某处文字/布局看起来很奇怪
