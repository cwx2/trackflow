## 操作流程

**第一步：打开系统，看大局**

1. 访问 http://localhost:3000，登录
2. 进项目，看当前 Sprint 的整体状态
   - 完成了多少？还剩多少？快到截止了吗？
   - 有没有燃尽图，趋势正不正常？
   - 看一眼各成员手头各有几个工单，有没有人太忙或没活干的

**第二步：处理 Code Review 队列**

找到状态是 Code Review 的工单，逐个打开：
- 看开发人员在评论里说了什么
- 给出 Review 意见（写在评论里）
- Review 通过 → 改状态为 Testing，评论里说一句通过了
- Review 不通过 → 改回 In Progress，评论里说清楚哪里有问题

**第三步：分配未分配的工单**

筛选当前 Sprint 里没有负责人的工单：
- 打开每个工单看一眼，根据工作量和合适程度分配给合适的开发人员
- 分配完后在工单上写一句说明为什么分给这个人（或者不写，看心情）
- 分配后确认工单负责人字段确实更新了

**第四步：看关联和依赖关系**

找一个有 blocks / is blocked by 关联的工单：
- 被 block 的工单进度怎么样，block 的原因是什么？
- 依赖的工单完成了吗？如果完成了，被 block 的工单可以继续了吗？
- 看看工单的截止日期，有没有因为 block 导致快超期的情况

**第五步：处理情况 E——Sprint 管理**

如果是要做新 Sprint 规划：
- 新建一个 Sprint，填好名称、开始日期、结束日期
- 加一句 Sprint 目标说明这个 Sprint 要做什么
- 从 Backlog 里挑工单加进来（看优先级和工作量）
- 启动 Sprint

如果是要完成老 Sprint：
- 点击 Complete Sprint
- 看看有哪些工单没完成，决定移到下个 Sprint 还是 Backlog
- 确认处理完了

**第六步：随手记录遇到的问题**

操作过程中遇到任何不对劲都记下来，比如：
- Sprint 进度数字看起来跟实际对不上
- 分配负责人的下拉搜索人名找不到
- 关联关系点进去跳转有问题
- Sprint 完成弹窗不知道该怎么操作
- 某个按钮应该有但找不到
- 界面某些地方排版乱或者信息显示不全
- 操作完了但页面没有刷新更新状态
