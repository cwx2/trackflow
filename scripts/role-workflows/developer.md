## 操作流程

**第一步：打开系统，看今天有什么活**

1. 访问 http://localhost:3000，用随机选的账号登录
2. 看一下主页或者工单列表，找到分配给自己的工单
3. 按优先级或截止日期排个序，决定先做哪个

**第二步：打开一个工单，仔细看需求**

随便找一个状态是 Open 或 In Progress 的工单打开，把它当成今天真实要处理的任务：

- 读标题和描述，搞清楚这个工单要做什么
- 看一眼右侧字段面板：优先级、截止日期、所属 Sprint、估算工时
  - 截止日期是什么？还有几天？快到了吗？
  - 有估算工时吗？自己觉得合理不合理？
- 看评论区：有没有之前的讨论、上次 Review 的意见、测试人员的反馈
- 看活动历史：这个工单经历了什么，谁改过什么
- 看关联工单：有没有 blocks/depends on 的关系，依赖的工单完成了吗？
- 看附件：有没有设计稿、截图、说明文件，点开看看能不能预览

**第三步：开始干活，更新工单状态**

把工单状态改成 In Progress（如果还不是的话），然后：
- 在评论区写一句话说明自己打算怎么做，或者遇到了什么问题
- 如果有估算工时，顺手更新一下实际花费时间

**第四步：遇到情况 B 时——处理被打回的工单**

找到测试人员打回来的工单（In Progress 状态，有测试人员的最新评论）：
- 看清楚测试人员说的问题是什么
- 在评论里回复说明修复方案
- 上传一个修复说明截图或文件（作为附件）
- 把状态改回 Code Review 或 Testing

**第五步：顺手看一眼 Sprint 进度**

进 Sprint 视图看看：
- 整个 Sprint 完成了多少？
- 自己名下还有几个未完成的？
- 有没有快到截止日期但还没开始的工单？

**第六步：随手记录遇到的问题**

上面操作过程中，任何让你觉得不对劲的地方都记下来，比如：
- 按钮点了没反应
- 页面显示的数据看起来不对
- 操作步骤太繁琐，应该有更简单的方式
- 界面某个地方显示乱了、字重叠了、颜色奇怪
- 应该有的功能找不到
- 某个弹窗/提示信息不清楚
- 加载太慢、转圈圈停不下来
