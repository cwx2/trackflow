## 1. 问题描述

作为测试人员（tester 角色，账号 zhaojing），打开分配给自己测试的工单详情页（如 DE4-1614，"测试人员"字段为赵静），附件区域显示：

- 标题：附件 0
- 内容：暂无附件

**但没有任何上传按钮、拖拽区域或操作入口。**

测试人员完成工单验收后，需要截图作为测试通过/失败的证据上传到工单附件中，这是测试工作流的核心操作之一。当前实现使测试人员无法在工单中留下视觉证据。

## 2. 复现步骤

1. 使用 zhaojing 账号（tester 角色）登录系统
2. 点击左侧"待测试工单" Saved Query
3. 打开 DE4-1614 工单详情页（该工单"测试人员"字段为赵静）
4. 查看附件区域 —— 仅显示"暂无附件"文字，无任何上传操作入口

## 3. 期望结果

附件区域应该显示：
- 明确的"上传附件"按钮
- 拖拽上传提示区域（如"点击浏览或将文件拖到此处"）
- 对于已有附件的工单，同样应在附件列表下方显示上传入口

在 YouTrack 中，附件区域始终提供清晰的上传入口，无论当前有无附件。

## 4. 差异分析

| 角色权限感知 | 有权限时显示上传按钮 | 不显示任何按钮 | 无法判断是无权限还是功能缺失 |

## 5. 验收标准

- [ ] 工单详情页附件区域在"暂无附件"状态下显示上传按钮
- [ ] 有拖拽上传提示区域
- [ ] 测试人员（tester）角色可以成功上传附件到分配给自己测试的工单
- [ ] 上传成功后附件立即显示在列表中
- [ ] 上传失败时有明确的错误提示

## 6. 备注

- 与 REQ-689（测试人员在非自己负责的工单详情页无法上传附件）问题不同：本需求描述的是即使在自己负责测试的工单中，也找不到上传入口

### 根因分析
REQ-691 描述的问题与 REQ-689 完全相同：工单详情页附件区域对拥有 `issue:manage_attachments` 权限但没有 `issue:edit` 权限的用户（如测试人员）不显示上传入口。

根因是原实现中附件区域的 readonly 状态仅依赖 `canEditIssueEffective`，未考虑独立的 `issue:manage_attachments` 权限。
